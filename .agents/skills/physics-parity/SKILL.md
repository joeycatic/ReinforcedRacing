# Physics parity (Python ↔ TypeScript)

The simulation exists twice: Python in `sim/` is the source of truth, and `web/src/sim/` is a TypeScript port that runs the trained policy in the browser. If they drift apart, the AI drives differently in the browser than it did in training. Every change to shared simulation code must land in both, in the same commit.

## What counts as shared simulation code

- Car physics: forces, integration, steering limits, wall contact, respawn
- Track geometry: spline, resampling, boundaries, checkpoints, JSON format
- Progress tracking: centerline projection, laps, wrong-way detection
- Observation builder: rays, normalization, field order (`obs` version)
- Any config value these read (`configs/physics.yaml`, observation constants)

Reward, PPO, logging, and rendering are not shared and do not need porting.

## Procedure

1. **Change Python first.** Make the change in `sim/`, update or add pytest tests, run `make test` for the Python side.
2. **Port to TypeScript.** Mirror the change in `web/src/sim/` using the same algorithm and the **same order of operations**. Use plain JS numbers (float64). Do not "simplify" or refactor the math on only one side.
3. **Bump versions if behavior changed.**
   - Physics behavior changed → bump `PHYSICS_VERSION` in both languages.
   - Observation layout or normalization changed → bump `OBS_VERSION` in both, update `sim/OBSERVATION.md`, and note that existing checkpoints are incompatible.
   - Track JSON format changed → bump the track format version.
4. **Regenerate fixtures.** Run the fixture generator for `tests/fixtures/parity/`. Never hand-edit fixture files, and never regenerate them to make a failing TypeScript test pass without first understanding the difference.
5. **Run both suites.** `make test` must pass for pytest and vitest. Parity tolerance is max absolute error ≤ 1e-6 on state and observations over 600 physics steps.
6. **Check the manifest.** After `make export`, `web/public/assets/manifest.json` must list the new versions, and the web app must refuse to load assets with mismatched versions.
7. **Record it.** Add a line to `DECISIONS.md` if the change altered car feel or the observation.

## When a parity test fails

- Find the **first** step where values diverge and which field diverges first. The first divergent field almost always points at the bug.
- Usual causes, in order: different operation order, a missed clamp or rate limit, degrees vs radians, angle wrapping (`atan2` range, `% 2π` handling), integer vs float division, a config value read on one side but hardcoded on the other, iteration order in the centerline search window.
- Tiny differences from `Math.sin`/`np.sin` are acceptable only within the 1e-6 tolerance. If drift grows over time, it is a real bug, not floating point noise.
- Do not loosen the tolerance to make tests pass.

## Done when

- Both test suites pass, versions are consistent in both languages and the manifest, fixtures were regenerated by the script, and the change exists in exactly the same form on both sides.
